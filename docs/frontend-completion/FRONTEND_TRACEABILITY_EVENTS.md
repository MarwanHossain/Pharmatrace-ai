# PharmaTrace AI — Frontend Traceability Event Architecture
## Phase 2 Structured QR Observation & Custody Transaction Model

**Date:** 2026-11-13  
**Scope:** Frontend-only persistent event stream (`client/src/services/traceabilityEvents.js`, stored under `pharmatrace.demo.data.v1.data.traceabilityEvents` via Web Locks)

---

## 1. Purpose & Separation of Concerns

PharmaTrace AI distinguishes between **scanning/verification observations** and **authoritative custody/state transactions**:

- **Observations (`category: 'observation'`):** Recorded when an operator scans or enters a QR verification URL / package serial at a portal checkpoint (or when a consumer clicks Verify on `/verify`). **Observations alone never transfer package custody, release batches, or mark shipments dispatched/received/dispensed.**
- **Transactions (`category: 'transaction'`):** Emitted strictly inside authorized transactional business mutations (`mutateDispatchShipment`, `mutateRecordReceivingSession`, `mutateDispensePackage`) after domain eligibility checks pass. Calling `mutateRecordTraceabilityEvents` with `category: 'transaction'` is explicitly rejected to prevent spoofing authoritative custody transitions.

Both event categories append chronologically into the `traceabilityEvents` array inside the versioned `localStorage` envelope (`pharmatrace.demo.data.v1`), protected across tabs by `navigator.locks.request(DEMO_DATA_LOCK_NAME)`.

## 2. Event Record Schema

Every record generated by `createTraceabilityEventRecord()` (`client/src/services/traceabilityEvents.js`) follows a consistent structure:

| Field | Type | Description |
| :--- | :--- | :--- |
| `id` | `string` | Monotonic sequential identifier (`evt-1`, `evt-2`, ...), collision-guarded across deletions/gaps. |
| `eventType` | `string` | Canonical constant from `TRACEABILITY_EVENT_TYPES`. |
| `packageId` | `string \| null` | Canonical normalized package serial (`serial`), or `null` if unavailable. |
| `serial` | `string \| null` | Uppercased package serial parsed cleanly from QR URL or plain input. |
| `batchId` | `string \| null` | Resolved internal batch identifier (`b1`, `b2`, ...) when registered in `packages`. |
| `actorUserId` | `string \| null` | Active authenticated user ID (`u1`, `u2`, ...), or `null` for anonymous public checks. |
| `actorRole` | `string \| null` | Actor role (`manufacturer`, `distributor`, `wholesaler`, `pharmacy`, `investigator`, `admin`, `public_customer`). |
| `organizationId` | `string \| null` | Active organization ID (`m1`, `d1`, `w1`, `p1`, or custom Admin org), or `null` for public/platform roles. |
| `shipmentId` | `string \| null` | Linked shipment reference (`SHP-XXXX`), when applicable. |
| `timestamp` | `string` | ISO 8601 UTC timestamp (`new Date().toISOString()`). |
| `checkpoint` | `string` | Workflow checkpoint identifier (e.g. `manufacturer_pre_dispatch`, `distributor_receiving`, `pharmacy_pre_dispense`, `public_verification`). |
| `category` | `'observation' \| 'transaction'` | Separates scan observations from custody-changing business transactions. |
| `outcome` | `string` | Execution outcome: `'success'`, `'failed'`, `'blocked'`, `'unmatched'`, `'duplicate'`, `'quarantined'`, `'missing'`, `'rejected'`, or public state (`'verified'`, `'dispensed'`, etc.). |
| `failureReason` | `string \| null` | Human-readable explanation when `outcome !== 'success'` (or consumer state note on non-verified public check), otherwise `null`. |

## 3. Canonical Event Types (`TRACEABILITY_EVENT_TYPES`)

| Supply-Chain Stage | Event Type | Category | Checkpoint | Trigger / Semantics |
| :--- | :--- | :--- | :--- | :--- |
| **Manufacturer** | `MANUFACTURER_QR_VERIFIED` | `observation` | `manufacturer_pre_dispatch` | Package QR URL/serial verified in active Manufacturer custody before dispatch. Unlocks `requireQrVerification` gate for that package. |
| **Manufacturer** | `MANUFACTURER_QR_VERIFICATION_FAILED` | `observation` | `manufacturer_pre_dispatch` | Pre-dispatch scan failed (wrong org custody, QA pending, expired, quarantined, off-manifest, or unknown serial). Keeps dispatch locked. |
| **Manufacturer** | `MANUFACTURER_DISPATCHED` | `transaction` | `manufacturer_dispatch` | Emitted per manifest serial when `mutateDispatchShipment` confirms dispatch (shipment `in_transit`, packages `in_transit`). |
| **Distributor** | `DISTRIBUTOR_RECEIVING_SCANNED` | `observation` | `distributor_receiving` | Distributor scans QR/serial inside `ReceivingModal` against incoming manifest. Does not transfer custody yet. |
| **Distributor** | `DISTRIBUTOR_RECEIVING_VERIFIED` | `observation` | `distributor_receiving` | Paired manifest/lock verification result (`success`, `unmatched`, `duplicate`, or `blocked`). |
| **Distributor** | `DISTRIBUTOR_RECEIVED` | `transaction` | `distributor_receiving` | Emitted per action on **Save Receiving Session** (`mutateRecordReceivingSession`): transfers custody (`accepted` -> `d1`, `damaged` -> `d1` quarantine). |
| **Distributor** | `DISTRIBUTOR_PRE_DISPATCH_SCANNED` | `observation` | `distributor_pre_dispatch` | Distributor scans unit QR/serial while building or dispatching an outgoing shipment. |
| **Distributor** | `DISTRIBUTOR_PRE_DISPATCH_VERIFIED` | `observation` | `distributor_pre_dispatch` | Pre-dispatch custody/eligibility verification (`success` unlocks Distributor Dispatch modal). |
| **Distributor** | `DISTRIBUTOR_DISPATCHED` | `transaction` | `distributor_dispatch` | Emitted per manifest serial on confirmed `mutateDispatchShipment` to Wholesaler. |
| **Wholesaler** | `WHOLESALER_RECEIVING_SCANNED` | `observation` | `wholesaler_receiving` | Wholesaler scans QR/serial inside `ReceivingModal` against incoming manifest. |
| **Wholesaler** | `WHOLESALER_RECEIVING_VERIFIED` | `observation` | `wholesaler_receiving` | Paired manifest/lock verification result for Wholesaler receipt session. |
| **Wholesaler** | `WHOLESALER_RECEIVED` | `transaction` | `wholesaler_receiving` | Emitted per action on **Save Receiving Session** (`accepted` -> `w1`). |
| **Wholesaler** | `WHOLESALER_PRE_DISPATCH_SCANNED` | `observation` | `wholesaler_pre_dispatch` | Wholesaler scans unit QR/serial for outgoing Pharmacy shipment or Dispatch Modal checkpoint. |
| **Wholesaler** | `WHOLESALER_PRE_DISPATCH_VERIFIED` | `observation` | `wholesaler_pre_dispatch` | Pre-dispatch custody/eligibility verification (`success` unlocks Wholesaler Dispatch modal). |
| **Wholesaler** | `WHOLESALER_DISPATCHED` | `transaction` | `wholesaler_dispatch` | Emitted per manifest serial on confirmed `mutateDispatchShipment` to Pharmacy. |
| **Pharmacy** | `PHARMACY_RECEIVING_SCANNED` | `observation` | `pharmacy_receiving` | Pharmacy scans QR/serial inside `ReceivingModal` against incoming manifest. |
| **Pharmacy** | `PHARMACY_RECEIVING_VERIFIED` | `observation` | `pharmacy_receiving` | Paired manifest/lock verification result before saving Pharmacy session. |
| **Pharmacy** | `PHARMACY_RECEIVED` | `transaction` | `pharmacy_receiving` | Emitted per action on **Save Receiving Session** (`accepted` -> `p1`). |
| **Pharmacy** | `PHARMACY_PRE_DISPENSE_SCANNED` | `observation` | `pharmacy_pre_dispense` | Explicit lookup/scan inside **Verify & Dispense** (`handleLookup`). Not emitted in React `useEffect`. |
| **Pharmacy** | `PHARMACY_PRE_DISPENSE_VERIFIED` | `observation` | `pharmacy_pre_dispense` | Evaluates expiry, unbroken chain, pharmacy custody, and non-dispensed state (`success` vs `blocked` / `failed`). |
| **Pharmacy** | `PHARMACY_DISPENSED` | `transaction` | `pharmacy_dispense` | Emitted when **Confirm Dispense** succeeds (`mutateDispensePackage`); transitions package to `dispensed` and blocks reuse. |
| **Public Customer** | `PUBLIC_VERIFICATION_RECORDED` | `observation` | `public_verification` | Emitted solely on explicit **Verify** / **Record Verification Check** click (`verifyAndRecord`) on `/verify`; read-only `/verify?serial=...` opens, refreshes (`F5`), and `/verify/results/:serial` never emit this event. |

## 4. Boundary-Aware Pre-Dispatch Gate (`hasCurrentPreDispatchVerification`)

`hasCurrentPreDispatchVerification(events, { serial, orgId, role })` scans `traceabilityEvents` in reverse chronological order for `serial`:

- Returns `{ verified: true, event }` only if the most recent relevant event for `(orgId, role)` is the role's pre-dispatch success event **after** any custody boundary transaction (`*_DISPATCHED`, `*_RECEIVED`, `PHARMACY_DISPENSED`).
- Earlier Manufacturer verification is invalidated once `MANUFACTURER_DISPATCHED` and `DISTRIBUTOR_RECEIVED` occur; Distributor and Wholesaler must each perform fresh pre-dispatch QR verification while holding active custody.
- `mutateDispatchShipment(..., { requireQrVerification: true })` enforces this check atomically inside the exclusive Web Lock transaction in addition to the Dispatch Modal UI checkpoint (`PreDispatchQrCheckpoint`).
